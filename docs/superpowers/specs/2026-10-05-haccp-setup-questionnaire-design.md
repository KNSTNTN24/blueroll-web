# «Настроить мой HACCP» — диалоговый опросник (Design Spec)

**Дата:** 2026-10-05 · **Статус:** на ревью · **Автор решений:** Костя (сессия 05.10.2026)
**Заменяет:** `blueroll-crm/docs/telegram-onboarding-bot-spec.md` (Telegram-бот с распознаванием фото меню и PDF — отклонён из-за стоимости распознавания изображений; тот документ помечается «superseded»).

## 1. Цель

Клиент Blueroll проходит в веб-приложении короткий диалог (10–15 минут), после которого у него:
1. **базовый набор чеклистов**, подобранный под то, что реально делает его кухня;
2. **заполненный HACCP-документ** (наш SFBB-пак, `haccp_pack_data`) — всё, что можно вывести из ответов.

Опросник **максимально опирается на правила FSA (SFBB) и внутренние документы Blueroll**, а не на модель. Модель — только точечный помощник. Фото меню и PDF в этой версии **не распознаются** (дорого).

**Не цели v1:** мобильное приложение (будет v2; в мобилке — кнопка «Открыть в вебе»), паб/фудтрак/кейтеринг/школьные и care-кухни, создание аккаунтов сотрудников, меню и аллергены блюд (у них свой поток), подпись HACCP-документа (делает владелец существующей кнопкой).

**Критерии успеха:**
- новый клиент без помощи команды получает рабочий набор чеклистов и HACCP-документ, по которому EHO видит покрытие всех применимых разделов SFBB;
- одинаковые ответы всегда дают одинаковый результат (детерминизм, объяснимость перед EHO);
- стоимость модели на одного клиента — копейки (измеряется логами, см. §8).

## 2. Решения (из брейншторма)

| Вопрос | Решение |
|---|---|
| Кто ведёт разговор | **Гибрид:** каркас — сценарий из данных; модель отвечает на свободные вопросы и разбирает свободный ввод |
| Где | **Внутри приложения**, отдельный раздел «Настроить мой HACCP» (не в регистрации), можно пройти в любой момент и повторно |
| Платформа | **Сначала веб** (Next.js), мобилка — v2 |
| Применение | **Черновик → подтверждение → применить**; чеклисты создаются выключенными |
| Повторное прохождение | **Добавляем недостающее, ручные правки владельца не трогаем** |
| Типы заведений v1 | Ресторан/кафе с кухней, кофейня, takeaway/доставка, пекарня/кондитерская |
| Архитектура | **A:** опросник как данные + детерминированный движок + модель точечно |

## 3. Архитектура

```
Веб: /haccp-setup (раздел «Настроить мой HACCP»)
 ├─ UI чат-окно: реплика-вопрос → ответ кнопками/полями; «Почему мы спрашиваем», «Задать вопрос»; прогресс по 5 разделам SFBB
 ├─ Движок диалога (чистые функции, src/lib/haccp-setup/engine.ts): ответы → следующий вопрос
 ├─ Генератор черновика (чистые функции, src/lib/haccp-setup/draft.ts): ответы → {чеклисты, поля HACCP, причины}
 ├─ Данные опросника (src/lib/haccp-setup/content/): questions, checklist library, haccp mappings, thresholds — версионируются
 ├─ Применение (server action / route, src/app/(dashboard)/haccp-setup/actions.ts): одна транзакционная операция
 └─ Помощник (Supabase Edge Function haccp-assistant, Claude Haiku 4.5): разбор свободного ввода + ответы по базе знаний
Supabase: haccp_setup_sessions (прогресс, ответы, журнал применения), checklist_templates/items (существующие), haccp_pack_data (существующий)
```

**Определения HACCP-пака выносятся в общий модуль.** Сейчас `HACCP_METHODS` (26 методов, 5 разделов, id полей) объявлены внутри `src/app/(dashboard)/haccp-pack/page.tsx`. Они переносятся в `src/lib/haccp-pack/methods.ts` без изменения содержимого, чтобы UI пака и генератор опросника использовали одно определение; тест проверяет, что каждый id поля в маппингах опросника существует.

## 4. Опросник как данные

**Вопрос** (`content/questions.ts`, типизированно):
`id`, `text` (EN, тон Blueroll), `why` («почему мы спрашиваем»), `section` (cross/cleaning/chilling/cooking/management), `answer`: `yes_no | single | multi | number | equipment_list | free_text`, `options`, `showIf` (выражение над ответами), `defaultsByType` (стартовые ответы для 4 типов заведений).

**Ход (~25–40 вопросов, показываются только применимые):**
1. **Профиль:** тип заведения; процессы — горячая кухня, охлаждение приготовленного, разогрев, горячая раздача, готовое к употреблению, разморозка, приём поставок, доставка клиентам; страна точки (Англия/Уэльс/Сев. Ирландия vs Шотландия — из данных точки, не спрашиваем).
2. **Оборудование:** список холодильников/морозильников/витрин/шокера/посудомойки/термощупов — ввод по одному или свободным текстом (помощник разбирает, клиент подтверждает).
3. **Процессы по разделам SFBB** (только применимые ветки): перекрёстное загрязнение и аллергены → уборка → охлаждение → приготовление → управление.
4. **Люди и практики:** ответственные, обучение, вредители (подрядчик / своими силами), поставщики.
5. **Черновик → подтверждение → применение.**

Тип заведения — **стартовые ответы**, не жёсткая ветка: всё уточняется вопросами о процессах (смешанные заведения покрываются).

**Прогресс:** таблица `haccp_setup_sessions` — `id, business_id, site_id, questionnaire_version, answers jsonb, status (in_progress|draft_ready|applied|abandoned), applied_summary jsonb, created_by, created_at, applied_at`. RLS — как у `haccp_pack_data` (business-level, только owner/manager/admin группы). Можно закрыть и продолжить.

## 5. Библиотека чеклистов и правила

`content/checklists.ts` — шаблоны с ключом `library_key` (стабильный id шаблона в библиотеке):
`name, sfbb_section, frequency (daily|weekly|monthly|four_weekly|custom), deadline_time?, assigned_roles (непусто), items[{name, item_type (tick|temperature|text|yes_no|photo|initials), required, min_value?, max_value?, unit?, description?}], includeIf, perEquipment?` (размножение пункта по списку оборудования нужного вида).

**Стартовый набор (~15–20):** открытие смены; закрытие смены; температуры холодильников/морозильников (пункт на единицу); приёмка поставок; температура приготовления (≥75 °C); горячая раздача (≥63 °C); охлаждение (<8 °C за 90 мин); разогрев (≥75 °C; Шотландия ≥82 °C); разморозка; калибровка термощупа (лёд −1…1 °C, кипяток 99…101 °C); посудомойка (ополаскивание ≥82 °C); еженедельная глубокая уборка; проверка аллергенов/новых блюд; вредители (своими силами — проверка, подрядчик — отметка визитов); 4-недельный HACCP-обзор; витрина/выпечка (пекарня). Источники: 6 текущих стандартных (`src/lib/seed-checklists.ts`), `BOBO_master_checklist_set.md`, пороги FSA.

**Пороги FSA** — единственный источник `content/thresholds.ts` (используется и существующим `ai-generate-checklist` при следующей правке — отдельная задача).

**Причины:** каждое включение в черновике несёт человеко-читаемую причину из `includeIf` («потому что вы держите блюда горячими»).

## 6. Заполнение HACCP-документа

`content/haccp-mapping.ts` — для полей `HACCP_METHODS`:
- **toggle/select** — значение из ответов напрямую;
- **text** — **шаблон с подстановками** по формулировкам SFBB (без модели), напр. для chilled_storage: «Chilled equipment: {fridges}. Temperatures are checked {frequency} with a probe; acceptable range 0–5 °C. If out of range: {action}.»;
- поля с существующим авто-заполнением (`autoSource`: рецепты, поставщики, документы, команда) — **не трогаем**.

**Пометка источника:** в `haccp_pack_data.data` добавляется `sources: {fieldId: "questionnaire"}`. Существующий механизм `overrides[fieldId]=true` (ручная правка) имеет приоритет.

**Правило записи при применении:** поле пишется, только если оно **пустое** или **`sources[field]=="questionnaire"` и нет `overrides[field]`**. Ручное — никогда.

## 7. Черновик и применение

**Экран черновика:**
- «Чеклисты»: список с причинами, у каждого чекбокс (по умолчанию вкл.); уже существующие (тот же `library_key` у бизнеса/точки) — помечены «уже есть», не создаются;
- «HACCP-документ»: раздел → поле → предлагаемое значение; статусы «новое» / «уже заполнено, останется» / «изменено вручную, не трогаем»;
- кнопка «Применить».

**Применение (сервер, одна транзакция):**
- создаёт выбранные шаблоны: `active=false`, `is_default=false`, `library_key`, непустые `assigned_roles` **и** `assigned_role_ids` (бэкфилл RBAC — иначе шаблон невидим), `site_id` точки;
- повторное прохождение: шаблон с тем же `library_key` не дублируется; новое оборудование → пункты добавляются только в шаблоны, созданные опросником и не изменённые вручную (по `updated_at` vs `created_at` и меткам), иначе в черновике отдельной строкой «добавить пункт X в чеклист Y» (по чекбоксу);
- пишет поля пака по правилу §6;
- сохраняет `applied_summary` (что создано/записано, версия опросника) в `haccp_setup_sessions`;
- после — экран «Готово: включите чеклисты и проверьте/подпишите HACCP-документ» со ссылками.

**Схема:** `checklist_templates.library_key text null` (+ уникальный индекс `(business_id, site_id, library_key) where library_key is not null`).

## 8. Помощник (модель)

**Edge Function `haccp-assistant`** (ключ только на сервере, отдельный API-ключ продукта с лимитом расходов в Console; модель `claude-haiku-4-5-20251001`):
1. **`parse_equipment(text)`** → `[{kind: fridge|freezer|display_chiller|blast_chiller|dishwasher|probe|other, label}]` строго по схеме (structured output); клиент подтверждает.
2. **`answer(question, context)`** → ответ **только по базе знаний** + ссылки на источники. База знаний: `content/knowledge/*.md` — выдержки SFBB (Open Government Licence, с указанием источника и страницы) + памятки Blueroll + пороги; поиск — полнотекстовый по чанкам (без векторов). Нет ответа в базе → «уточните у вашего EHO». Вне темы — отказ. Ответы помощника **не меняют** ответы опросника и черновик.

**Без модели опросник работает полностью:** свободный ввод оборудования → ручное добавление по одному; «Задать вопрос» скрыт.

**Лимиты и учёт:** ≤ 30 обращений на бизнес в сутки; `max_tokens` ограничен; каждый вызов пишется в `ai_usage_log` (business_id, функция, input/output tokens, ts) — реальная стоимость на клиента по факту.

**Безопасность:** текст клиента — данные, не инструкции (в системном промпте); помощник не имеет инструментов записи; персональные данные клиента в промпт не передаются (только вопрос и минимальный контекст: тип заведения, раздел SFBB).

## 9. Тестирование

- **Золотые тесты генератора:** 4+ профиля (кофейня без кухни; ресторан с горячей раздачей и охлаждением; takeaway с доставкой; пекарня с витриной) → ожидаемый точный набор `library_key` и значения полей пака. Любое изменение правил видно в diff.
- **Валидация контента (тест):** у каждого вопроса есть `section`; нет недостижимых вопросов; все `showIf`/`includeIf` ссылаются на существующие ответы; все id полей маппинга существуют в `HACCP_METHODS`; пороги совпадают с `thresholds.ts`; у каждого шаблона непустые `assigned_roles`; `item_type`/`frequency` из разрешённых значений.
- **Движок:** переходы, `showIf`, продолжение сессии, повторное прохождение.
- **Применение:** не дублирует `library_key`; не трогает `overrides`; бэкфилл `assigned_role_ids`; чеклисты `active=false`.
- **Помощник:** набор 20–30 вопросов — есть ссылка на источник, нет цифр вне базы, отказ вне темы; `parse_equipment` — 10 фраз (в т.ч. смешанные, опечатки).

## 10. Фазы

- **v1 (этот документ):** веб, 4 типа, опросник, библиотека ~15–20 шаблонов, заполнение пака, черновик/применение, помощник (вопросы + разбор оборудования), лимиты и учёт.
- **v2:** мобилка (Flutter), больше типов (паб, фудтрак, кейтеринг), перенос ответов на новую точку, возможно — распознавание меню как платная опция.

## 11. Открытые вопросы

1. Язык интерфейса опросника — английский (клиенты UK); подтверждаем?
2. Доступ к разделу — owner и manager (как к HACCP-паку)? Сотрудники кухни не видят.
3. Лимит 30 обращений к помощнику в сутки на бизнес — ок?
4. Включаем ли раздел для триальных бизнесов (да — это часть ценности на триале) или только платящим?
